# Migrating to qmlqualitylens 0.5

Version 0.5 adds coverage, benchmark regression, reachability, and GitLab Code Quality. Artifacts and baselines use schema `0.5.0`. Regenerate reviewed baselines after upgrading from 0.4.

## Reachability

Lens automatically treats `Main.qml`, `shell.qml`, and components rooted in `Window`/`ApplicationWindow` as entrypoints. Applications with other roots can configure project-relative paths and dynamic creation edges:

```json
{
  "entrypoints": ["src/AppRoot.qml"],
  "dynamic_component_edges": [
    { "from": "src/AppRoot.qml", "to": "src/pages/PluginPage.qml" }
  ]
}
```

Reachability follows resolved component uses, literal `Loader.source` files, simple `sourceComponent` references, and configured edges. Without an entrypoint, cleanup falls back to incoming references and marks reachability unavailable.

## Coverage

Configure a Cobertura report, such as one generated by Qoverage:

```json
{ "reports": { "coverage": "target/coverage.xml" } }
```

`coverage_evidence.json` maps file/line observations separately to object creation, bindings, and function/handler ranges. It shows partial report scope. Coverage remains scenario evidence, not a universal percentage gate.

## qmlbench

```json
{
  "reports": {
    "qmlbench": "target/qmlbench.json",
    "qmlbench_baseline": "benchmarks/linux-baseline.json"
  },
  "benchmark_policy": {
    "max_regression_percent": 5,
    "max_coefficient_of_variation": 0.05,
    "min_samples": 5
  }
}
```

Comparisons require matching benchmark names, Qt, OS/QPA, OpenGL, and window size. Mismatched or noisy data is incomplete or warning evidence, not a trusted regression.

## GitLab Code Quality

Both `analyze` and `audit` accept `--format codeclimate`. Redirect the JSON array to a GitLab Code Quality artifact:

```sh
qmlqualitylens audit --config qmlqualitylens.config.json \
  --format codeclimate > gl-code-quality-report.json
```
